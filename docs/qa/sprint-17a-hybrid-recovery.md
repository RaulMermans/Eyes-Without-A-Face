## 3. Changes

- **Pre-send block** (RC-1, Workstream 2).
  - New pure helper `cloudBlockedTargets(plan)`. It uses the same rule as `categoryNeed.blocking`, so the notice and the button can never disagree.
  - While a required fixed-list field is provably unfillable, “Approve and send” is **disabled**. The headline reads **“Not ready to send”**, and `approval-blocked` names each field and why: no field chosen (with the top candidates), no category-like field, names not shareable, or names withheld.
  - Routes offered: choose the field, build on this device (or answer its questions), change the destination, “Don't send”.
  - Uncertainty Gemini can resolve (`id`, `email`, date matches) never blocks.
- **Sharing only for the chosen field** (RC-2). The notice offers “Share these names and prepare a new request” only for the field the user chose for a required target. With none chosen, it offers **“Choose the field for status”** instead. Nothing is ever shared automatically.
- **Incomplete-mapping recovery** (RC-3, Workstream 3).
  - New pure helper `unwrittenRequiredTargets(contract, destination)`.
  - The Result names the missing required fields in both the next-step line and the `guided-incomplete` panel. It explains that no record can be valid, says the work is kept, and offers “Answer the questions on this device” or “Build on this device”, and “Change the destination”.
  - **No operation is added**, and the mapping is shown as proposed. Validator, contracts and export eligibility are unchanged.
- **Date meaning copy** (RC-5, Workstream 4): “contract.signed_at, read as YYYY-MM-DD. The format is unambiguous, but EYES can't tell whether this date means “createdAt”. Look at the preview to be sure it's the right field.”
  - No correspondence is hard-coded. The user can reject the suggestion (it is never applied, Sprint 16B), choose another date field, or apply a custom destination whose field means “contract signed”.
- **Copy:** README recovery instructions; AGENTS § Hybrid journey recovery.
